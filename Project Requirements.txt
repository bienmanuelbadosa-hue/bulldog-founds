# Bulldog Founds — Low-Level Requirements (MVP-Focused)

## 1. MVP Goal

Deliver a working web application where authenticated NU Laguna users can:

1. Register/Login
2. Create lost/found item posts
3. Upload item images
4. Search and filter items
5. Contact item posters via Microsoft Teams
6. Update item status

The MVP prioritizes:

* Core business flow
* Stability
* Simplicity
* Clean OOP architecture
* Expandability

# 4.4 Authentication Module

---

## Functional Requirements

### Registration

The system shall:

* Validate email uniqueness
* Encrypt passwords using BCrypt
* Generate JWT after successful registration

### Login

The system shall:

* Validate credentials
* Generate JWT token
* Return authenticated user details

---

## JWT Requirements

| Requirement | Description   |
| ----------- | ------------- |
| Token Type  | Bearer Token  |
| Expiration  | 24 Hours      |
| Header      | Authorization |
| Algorithm   | HS256         |

# 4.5 API Endpoints

---

# Authentication APIs

## POST `/api/auth/register`

### Request

```json
{
  "firstName": "Juan",
  "lastName": "Dela Cruz",
  "email": "juan@nu-laguna.edu.ph",
  "password": "password123",
  "role": "STUDENT",
  "teamsLink": "https://teams.microsoft.com/..."
}
```

### Response

```json
{
  "token": "jwt-token"
}
```

---

## POST `/api/auth/login`

### Request

```json
{
  "email": "juan@nu-laguna.edu.ph",
  "password": "password123"
}
```

---

# Item APIs

---

## POST `/api/items`

Creates item post.

### Authorization

Authenticated users only.

### Multipart Form Data

| Field             | Type   |
| ----------------- | ------ |
| title             | String |
| color             | String |
| description       | String |
| lastKnownLocation | String |
| claimLocation     | String |
| additionalDetails | String |
| image             | File   |

---

## GET `/api/items`

Returns paginated item list.

### Query Parameters

| Parameter | Example    |
| --------- | ---------- |
| keyword   | wallet     |
| color     | black      |
| status    | UNRESOLVED |

---

## GET `/api/items/{id}`

Returns item details.

---

## PUT `/api/items/{id}/status`

Updates item status.

### Authorization Rules

| Role        | Permission |
| ----------- | ---------- |
| Post Owner  | Allowed    |
| Other Users | Denied     |

---

## DELETE `/api/items/{id}`

Allows owner to delete own post.

# 8. OOP Requirements

---

# Encapsulation

Entities must:

* Use private fields
* Use getters/setters

---

# Abstraction

Business logic must exist only inside services.

Controllers:

* Must not contain business logic.

---

# Inheritance

Optional future enhancement:

```text
User
├── Student
├── Faculty
└── Staff
```

For MVP:
Use enums instead of subclasses to reduce complexity.

---

# Polymorphism

Future enhancement:
Different role permissions.

# 11. Explicit MVP Simplifications

To avoid overengineering:

DO NOT include yet:

* Real-time chat
* Push notifications
* AI item matching
* Email verification
* Role-specific dashboards
* Admin moderation
* Complex RBAC
* Microservices
* WebSockets
* OAuth login

These can become Phase 2+ features after MVP stabilization.
